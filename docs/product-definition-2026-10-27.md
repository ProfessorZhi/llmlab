# LLM Lab 产品定义（2026-10-27 裁决版）

> **本文是唯一的产品定义。** 与本文冲突的其他文档，以本文为准；被本文取代的文档段落见 §8。
> 本文只定义「产品是什么、用户来做什么、哪些词只有一个意思」，不描述实现进度。实现缺口见 §3 的「现在」一列。

## 1. 一句话

**这台 GPU 机器上，谁的模型在跑、谁在调、还能不能跑，一眼看清；想给别人用，一个按钮开一个 API。**

## 2. 两条根决策

| # | 决策 | 含义 | 为什么 |
|---|---|---|---|
| **B1** | **当前产品是个人资源管理** | 每个人只看、只动自己名下的模型、引擎、服务和 API。跨用户共享暂缓。管理员以监控元数据为主，不代任何用户操作。 | 之前同时存在「共享模型池」和「个人资源管理」两份定义，界面按前者长、能力按后者实现，导致每个页面都在承诺做不到的事。 |
| **B2** | **平台可以起服务，但只由本人的代理执行** | 平台下发「启动/停止/重启」任务 → 该用户的 `llmlab agent` 以**他自己的 Linux 身份**执行（`systemctl --user start|stop`，或 user unit 之外的等价方式）→ 结果回报平台。**管理员只能「请求」，永不代跑**，root 不进这条路径。 | 用户要的是「在平台上点一下服务就起来」；而 `P2` 和 `docs/access-boundaries.md` 禁止平台以他人身份执行。代理执行是唯一同时满足两者的形状。 |

B2 的前置条件（未完成前，第 2 步仍是「给命令，你自己起」）：

- 代理必须能接收任务，而不只是上报：`docs/design-lab-resource-agent-and-service-sharing-2026-10-23.md:197-204` 设计了 `/api/serve/start|stop|restart` 与任务派发，`:438-439` 自认未实现。
- 每个用户的服务必须是**自己的 user unit**，否则代理停了也没法起。现有的 `strata.service` 已经是这种形状（用户级 user unit，由该用户自己的 systemd 管理），可作为模板。
- 启动结果必须回报：`started` / `already running` / `failed: <原因>`。**不能把「已下发」显示成「已启动」。**

## 3. 用户进来做的四件事

产品只有这四个动作，导航和页面都必须能归到其中之一。归不进去的，要么删，要么并。

| # | 动作 | 现在 | 缺口 |
|---|---|---|---|
| 1 | **我有什么** — 我的模型、装好的引擎、正在跑的服务 | 可用。模型与引擎自动入账，服务靠端口扫描/代理上报 | 服务行必须写清「最后一次确认在什么时候」；没有确认就不能显示「运行中」（见 §5 F1） |
| 2 | **起一个服务** — 选模型、选引擎、点启动 | **不可用**，只能回命令行自己起，平台给一段参数参考 | B2 的代理任务派发；起前的显存估计与端口占用检查；失败要说原因 |
| 3 | **给它一个 API** — 把服务发布成一个模型名，拿一把 key | 半可用。要手动在「API 接入」发布，另在「API 密钥」建 key | 自动发现的服务不进网关快照，两页之间断了一环；密钥有两套（见 §4） |
| 4 | **看谁在用** — 调用量、延迟、失败、最近的请求 | 可用，但只覆盖走网关的流量 | 直连流量不可见，需要在 UI 上说清「这部分不走网关，平台看不到」 |

**「方便了什么」必须能一句话答**（当前诚实的答案）：

1. 不用反复 `ssh` + `ps`/`ss`/`nvidia-smi` 才知道谁在跑、还剩多少显存；
2. 把一把**可撤销**的 key 给别人，而不用给 Linux 密码；
3. 启动参数有参考值，不用每次翻命令历史。

达不到这三条的功能，不进首版。

## 4. 一义一名

同一个东西只有一个词；同一个词只指一个东西。**这是「故事讲得清」的硬条件**，不是文案优化。

| 词 | 唯一含义 | 数据对象 | 不再用来指 |
|---|---|---|---|
| **模型** | 磁盘上的权重文件/目录 | `models` + `model_locations` | 网关里的模型名（那叫「API 名称」） |
| **推理引擎** | 装好的运行时（可执行文件、venv、源码树） | `runtime_builds` | 正在跑的进程（那是「推理服务」） |
| **推理服务** | 正在监听的一个进程 | `engines` | 网关路由、endpoint |
| **API 接入** | 把某个推理服务发布成 `POST /v1/chat/completions` 里的一个 `model` 名 | `gateway.routes` | endpoint、deployment |
| **密钥** | `sk-lab-` 网关密钥，**用户只有这一种** | `gateway.keys` | `sk-qwen-` 直连密钥（那是运维凭据，不进「我的 API」） |
| **可见性** | 两个值：`私有` / `全员`。**默认私有**，`全员` 在共享暂缓期间不可选 | 各表 `visibility` | endpoint ACL、`default_visibility`、`all_approved_platform_users` 等其余写法 |

**不面向用户的名词**：`deployment`、`endpoint`、`endpoint_grant`、`route_path`。它们留在数据模型里，但不出现在控制台的任何标题、列名、空状态文案里。个人模式下用户不需要知道这四层。

### 4.1 现状盘点与收口口径（2026-10-27 实测）

**密钥只有三类是真的**，其余都是演示值或测试夹具：

| 前缀 | 是什么 | 会不会下发 | 在「我的 API」里 |
|---|---|---|---|
| `sk-lab-` | 网关密钥，用户可撤销的那把 | 创建时返回一次明文，之后只给 `key_id` + 前缀 | ✅ 唯一出现的密钥 |
| `llmlab_` | CLI / Agent 的 scoped 令牌（`backend/auth/tokens.py:105`） | 签发与轮换时各返回一次明文 | ❌ 它属于「账户 → 令牌」，不是模型密钥 |
| `sk-qwen-` | 存量运维凭据（`backend/bff/model_service_keys.py:53`） | 每次查询都返回完整明文，但整个接口在 `personal_mode` 下 403 | ❌ 运维凭据，不进用户视野 |
| `llt_` / `llk_` | 前端硬编码的演示占位 | 不落盘 | 不是密钥。`llt_` 已删；`llk_` 只存在于 `/qa.html` 预览页 |

**可见性有八套写法，但只有两处是真列**：`gateway.routes.visibility`（`all`/`private`）与 `endpoints.visibility`（`private`/`users`/`all_approved_platform_users`）。`engines`、`models`、`deployments` 表没有这一列，它们的可见性是 `backend/registry/authz.py:84-130` 在运行时从引用它们的 endpoint 派生的。

**因此收口的口径是「只改出口，不改数据模型」**：

- 改的是 UI 与 BFF 输出里出现的词，不是数据库列的值域；
- `users`（逐人授权）**不迁移成 `all`** —— 那是把点名共享放大成全员，属于权限放大。B1 下它保持休眠；
- `default_visibility` 这类「全局默认」不再影响新服务，自动接入一律私有；
- 集成页的 `all`/`admin` 是**入口受众**，不是模型资源可见性，收敛时不并入二值，只改名。

### 4.2 被砍掉的多义词

- 「路由」曾同时指 gateway alias、registry `route_path`、`launch_json.route.name`。用户层只保留「API 接入」。
- 「可见性」曾有五套写法（endpoint `users/all_approved_platform_users`、gateway `all/private`、`lab_settings.default_visibility`、ops `private/shared`、登记向导 `private/all/selected`）。收敛为二值；向导里的选择当前**只写进 tag、不产生任何效果**，在 B1 下应当直接删掉这个选项，而不是留着假装可选。
- 「运行中」曾被三种状态拼出来：`status`（注册/验证）、`state`（发现循环）、`health_json`。对用户只保留一个结论 + 一个时间戳（见 §5 F1）。

## 5. 必须先修掉的「说了假话」

这几条不是体验问题，是**结论错误**，优先级高于任何新功能。

| # | 现象 | 证据 | 要求 |
|---|---|---|---|
| **F1** | 已停止 18 小时的 strata 在列表里显示「运行中 · 健康」 | 手工登记行 `launch_json=NULL` → `backend/registry/presence.py:6-12` 不判过期 → `web/console/js/viewmodel.js:99-100` 用 `status==='verified'` 显示「运行中/健康」，而该行 `health_json.state` 是 `degraded` | 服务行显示「最后确认 HH:MM」；超过探测窗口显示「未确认」；`health_json` 的结论必须显示，不能被 `status` 覆盖 |
| **F2** | 自动发现的服务不在 API 接入的候选里 | **原来的归因是错的。**`docs/registry-cli-contract.md:1096-1098` 讲的是 Gateway 快照那条链，而控制台的候选列表读的是 `/api/v2/ops`，与快照无关。真正的原因是**归属主体不是同一个字符串**：端口扫描把 owner 记成 `linux:<host>:<uid>`（`backend/registry/ingest_runner.py` 的 `by_uid`），会话主体是 `account:<id>`，而 `owner_is_self` 与可见性判定都是字符串全等。同一台机器上的同一件事，只因为「怎么被发现的」不同，就分属两个名字。代理上报路径本来就是对的（`account_for_linux_user`）。 | 第 1 步和第 3 步之间必须有路：发现到的服务直接出现在「发布为 API」的候选里 |
| **F3** | 「保存参数」旁边没有任何提示说明它没重启服务 | `web/console/js/service.js:107-110` 只写了「由本人重启」 | B2 落地前保留这句；落地后改成「已下发给你的代理，等待重启结果」，且结果没回来前不显示「已生效」 |
| **F4** | 同一动作 4 个入口，关键动作 0 个入口 | 登记服务：概览按钮 / 服务页按钮 / 直达路由 / 发现记录内联，共 4 个、2 条流程；而 verify / share / repoint / rollback 有 API 无入口 | 每个动作只保留一个主入口，其余降为链接 |

## 6. 谁能做什么（个人模式）

| | 普通用户 | 管理员 |
|---|---|---|
| 看自己的模型/引擎/服务/调用 | ✅ | ✅ |
| 看别人的资源 | ❌ | ✅ 只读元数据 |
| 修改自己的服务参数 | ✅（B2 后由代理重启） | ❌ 不代改 |
| 启动/停止自己的服务 | ✅（经本人代理） | 只能「请求」，**永不代跑** |
| 启动/停止别人的服务 | ❌ | ❌ |
| 建/撤自己的密钥 | ✅ | ❌ 不代建、不代撤 |
| 看请求正文 | 仅本人、且该 key 开启记录 | ❌ 不看 |
| 建平台账户、改角色、停用 | ❌ | ✅ |

「管理员可以在 GPU 冲突时停任何服务」这一条**在 B1 + B2 下作废**：管理员没有执行路径。GPU 争用在个人模式下由用户自己协调。

## 7. 明确不做（本版本）

- 跨用户共享：`全员` 可见性、endpoint ACL、逐人授权。数据和 API 保留，UI 不出现。
- 平台冷启动别人的模型（按需拉起）。
- 硬性 GPU 配额/准入：当前什么也不拦，显存字段是 `null`。**在补上之前，必须在界面上说「平台不限制显存占用」**，不能让它看起来像有管控。
- 平台移动/删除用户文件、`storage move`。
- 外部 HTTPS 推理入口。
