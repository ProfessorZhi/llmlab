# 控制台数据可视化 — 设计文档

> 状态：**DRAFT / 实施依据**　日期：2026-10-23  
> 读者：实现这份设计的 Claude Code（本地）与审核者。  
> 范围：控制台（`web/console/`）的图表体系、历史数据层、各页面的图表设计。  
> 关联：[私有资源与服务共享 — 设计](../design-lab-resource-agent-and-service-sharing-2026-10-23.md)

## 0. 为什么要改

现在的控制台图表只有五种：旭日图、环形图、显存点阵、柱状图、热力图，而且几乎全是**某一刻的快照**。用户真正想知道的是：

1. **随时间怎么变**：显存从早上到现在谁在涨？CPU 什么时候被打满？
2. **按人分开看**：每个人占了多少？我占了多少？和别人比呢？
3. **离上限多远**：显存还剩多少、磁盘几天后会满、并发槽位还空几个——也就是「水位线」。
4. **分布而不是平均**：延迟的 P50 很好看，但长尾在哪里？

这些问题，快照加饼图都回答不了。本文定义：一套**图表组件库**、一层**历史数据**，以及**每个页面用哪种图回答哪个问题**。

## 1. 原则（实现与审核都按这个来）

1. **先定形式，最后定颜色。** 先问这张图要回答什么问题——比大小、看趋势、分辨身份、正负方向、占比、分布——再选图（§3）。答案有时根本不是图，而是一个数字卡片。
2. **未知 ≠ 0。** 缺测的时间段画成断线或留空，绝不连成 0。延续现有的硬规则。
3. **一张图一个纵轴。** 禁止双纵轴。两个量纲不同的量，用两张小图上下对齐（small multiples），共享时间轴。
4. **颜色跟着实体走，不跟排名走。** 同一个用户、模型、服务，在所有页面、所有时间范围、筛选前后都是同一种颜色（§2.2）。
5. **「我」是强调，不是另一种颜色。** 默认按人上色；切换到「突出我」时，只有我保留颜色，其他人一律退成灰色。
6. **每张图都有表格视图。** 卡片右上角提供「图 / 表」切换。tooltip 只是增强，不能是读到数值的唯一途径。
7. **细线、发丝网格、留白。** 线宽 2px；柱宽不超过 24px，顶端圆角 4px、底部方角；网格线是 1px 实线（不用虚线），颜色只比底色深一级；面积填充用约 10% 不透明度。
8. **筛选条只有一行，放在所有图的上方。** 时间范围排第一位，各图卡片内不再放自己的筛选。重新取数时保留上一帧并降低不透明度，不闪骨架屏。
9. **数字的字体规则。** 大数字（KPI、英雄数字）用比例数字；表格列和坐标轴刻度用 `tabular-nums`。

## 2. 视觉 token

### 2.1 分类色（8 槽，已用 dataviz 校验器验证）

现在 `charts.js` 里的 `SERIES_COLORS` **校验不通过**：`#A2845E` 饱和度太低，看起来是灰色；`#FF2D55` 和 `#34C759` 在绿色盲（deutan）下的色差只有 6.5。替换为下表，顺序是枚举所有排列后，选出两种模式下都通过的一种：

| 槽 | 色相 | 浅色模式（底色 `#FFFFFF`） | 深色模式（底色 `#1C1C1E`） |
| --- | --- | --- | --- |
| 1 | blue | `#0A6FE0` | `#3A8DF0` |
| 2 | orange | `#EE7A12` | `#D06A15` |
| 3 | teal | `#169CB3` | `#1E9DB2` |
| 4 | gold | `#C89200` | `#B08000` |
| 5 | purple | `#9B4DD0` | `#A970E0` |
| 6 | green | `#2B9A4A` | `#2F9C4D` |
| 7 | indigo | `#5550D0` | `#7C78E8` |
| 8 | pink | `#E0407A` | `#E25586` |

校验结果（相邻两槽，用于堆叠、柱、线）：

| 模式 | 色盲最差 ΔE | 正常视觉最差 ΔE | 对比度 |
| --- | --- | --- | --- |
| 浅色 | 15.9 | 23.6 | orange、gold 低于 3:1 ⇒ 必须带可见标签或表格视图 |
| 深色 | 15.3 | 21.4 | 全部 ≥ 3:1 |

复现命令：

```bash
node <dataviz>/scripts/validate_palette.js "#0A6FE0,#EE7A12,#169CB3,#C89200,#9B4DD0,#2B9A4A,#5550D0,#E0407A" --mode light --surface "#ffffff"
node <dataviz>/scripts/validate_palette.js "#3A8DF0,#D06A15,#1E9DB2,#B08000,#A970E0,#2F9C4D,#7C78E8,#E25586" --mode dark --surface "#1c1c1e"
```

**散点、气泡这类「所有颜色两两都要分得开」的图，最多用 3 色，固定为 blue、gold、pink**：两种模式下两两比较，色盲 ΔE 都 ≥ 11。超过 3 个系列就分面（small multiples），不要再加颜色。

**超过 8 个系列**时，尾部合并成「其他」（灰色）。绝不生成第 9 种颜色。

**每个实体的颜色固定**：按实体 id（用户 id、模型名、服务 id）做稳定哈希，映射到 1–8 槽，结果存进 `colorFor(kind, id)`。同一页面里出现冲突时，后出现的那个顺延到下一个空槽。这个映射在一个会话内不变，不随筛选改变。

### 2.2 其他色

| 用途 | 规则 |
| --- | --- |
| 顺序色（热力图、深浅表示量） | 单色相 blue，从浅到深：`#cde2fb → #9ec5f4 → #6da7ec → #3a8df0 → #0a6fe0 → #0857b3 → #06438a`。用于有序分级（ordinal）时，浅色模式从 `#6da7ec` 起步（已校验：浅端对比度 2.5:1）；深色模式的有序色阶由实现者用 `--ordinal --mode dark` 另行校验 |
| 发散色（相对基线的正负） | blue ↔ orange，中点为中性灰（浅 `#EFEFF1`，深 `#3A3A3C`） |
| 状态色（只表示好坏，不作系列色） | 沿用 `--green` / `--orange` / `--red`。状态必须配图标和文字，不能只靠颜色 |
| 强调模式的「其他人」 | 浅 `#C7C7CC`，深 `#48484A` |
| 容量线、阈值线 | 容量：1.5px 实线，用文字色；警戒带（如 80–95%）：`--orange` 8% 填充；危险线：`--red` 1px |
| 网格、坐标轴 | `--hairline`，1px 实线 |

所有 token 写进 `console.css` 的 `:root` 和深色媒体查询，名称为 `--viz-1` … `--viz-8`、`--viz-seq-1` … `--viz-seq-7`、`--viz-other`、`--viz-grid`。JS 一律读 CSS 变量，不再写死十六进制颜色。

## 3. 用什么图回答什么问题

| 问题 | 图 | 说明 |
| --- | --- | --- |
| 现在多少、比之前涨了还是跌了 | **KPI 卡片 + 迷你趋势线 + 变化量** | 当前值、与上个同等时段比的变化、最近 N 点的 sparkline |
| 随时间变化（一个量） | **折线 / 面积图** | 缺测断线 |
| 随时间变化，按人或服务拆开、看谁占了多少 | **堆叠面积图 + 容量线** | 「水位线」：顶部画总容量（如 48 GB），叠加警戒带 |
| 我和别人比 | **强调模式**（我上色，他人灰） | 与堆叠面积图共用一个开关 |
| 好几个相关的量（利用率、功耗、温度） | **共享时间轴的小图组** | 每张一个纵轴，十字准线在所有小图上联动 |
| 一个比例和它的上限 | **计量条 / 子弹图** | 磁盘、显存、槽位；子弹图可以再画「目标」和「上周同时」两个刻度 |
| 什么时候忙（周期规律） | **热力图**：星期 × 小时，或 用户 × 小时 | 顺序色，附色阶图例 |
| 30 天里每天的情况 | **日历热力图** | GPU 忙碌比例 |
| 谁在什么时候占着 GPU | **泳道时间线** | 每个用户 / 服务一条泳道，占用时段画成条 |
| 占比（某一刻） | **横向堆叠条**；只有在 ≤ 6 段、且差异明显时才用环形图 | 值彼此接近时不用环形图 |
| 层级占比（谁 → 哪类 → 多少） | **矩形树图**（磁盘）/ **旭日图**（调用者 → 模型） | 树图最多两层 |
| 流向（调用者 → 密钥 → 模型 → 服务） | **桑基图 / 冲积图**（3–4 列） | 节点颜色跟实体，连线用浅色 |
| 分布与长尾 | **直方图**、**分位带**（P50 线 + P5–P95 阴影带）、**箱线图**（按模型） | 不只看平均值 |
| 两个量的关系（输入 Token vs 延迟） | **散点图**（≤ 3 色，否则分面） | 用最近点命中，不要求精确点中 |
| 前后对比（版本 A vs B 的得分） | **哑铃图** | 评测页 |
| 显存「格子」直觉 | **点阵图**（已有） | 保留 |
| 磁盘几天后会满 | **折线 + 线性外推虚段** | 外推虚段是唯一允许的虚线，且必须标注「预测」 |

**不用的图**：3D 图、雷达图、双纵轴、彩虹色阶、两片的饼图、只有一根柱子的柱状图、每个数据点都标数字。

## 4. 历史数据层

### 4.1 现状

- 实时读数：`/api/infra/summary`（NVML）、`/api/infra/system`（直接读 `/proc`）、`/api/v2/engine/live`（Strata）。**全是瞬时值。**
- 网关的调用元数据存在 SQLite，**有历史**。
- Dell 上的 Prometheus 只抓了 `prometheus` 和 `strata` 两个目标，**没有 node_exporter**，所以主机和按用户的历史不存在。

### 4.2 方案：平台内置采样器 + SQLite 分层汇总

做法：在 BFF 进程里加一个后台采样线程（`backend/observability/history.py`），复用 `live_sources.py` 现有的读法。不需要 root，不依赖运维改动，也不引入第三方库。

| 采样 | 周期 | 内容 |
| --- | --- | --- |
| 主机 | 15 s | CPU 利用率、iowait、负载；内存已用、可用、swap；各盘读写速率、繁忙度；网络收发 |
| GPU（NVML） | 15 s | 利用率、显存已用 / 总量、功耗、温度；**每个进程的显存**（pid → uid → 用户 / 服务） |
| 按用户 | 30 s | 每个 Linux 用户的进程数、常驻内存、CPU（核）、显存 |
| 引擎 | 15 s | 每个服务：运行中 / 排队、槽位占用 token、生成 tok/s、prefill tok/s |
| 网关 | — | 直接用现有的 usage 表 |
| 磁盘容量 | 5 min | 各挂载点的已用、总量 |

**存储与降采样：**

- 表 `samples(metric, key, ts, value)`：原始数据保留 48 h。
- 表 `rollups(metric, key, tier, ts, min, avg, max, n)`：
  - `1m` 保留 7 d；
  - `10m` 保留 90 d；
  - `1h` 保留 2 年。
- 每分钟由同一线程汇总并清理过期数据。WAL 模式，文件权限 0600，放在 `state_dir/history.sqlite3`。
- **容量估算**：约 60 个指标 × 6 个 key × 每天 5760 点 ≈ 每天 200 万行原始数据，约 60 MB 并按 48 h 滚动；汇总层合计小于 200 MB。实现者需要实测并在 PR 里写明。

**缺测**：采样失败时写 `NULL` 值，不写 0。汇总时 `n=0` 的桶返回 `null`。前端遇到 `null` 一律断线。

**单一采样、两个消费者**：同一组读数也通过 `/metrics`（只监听 loopback）以 Prometheus 文本格式暴露。运维批准把它加为抓取目标之后，Grafana 就有了同样的历史，用于深度分析（§7）。在批准之前，控制台完全不依赖 Prometheus。

### 4.3 接口

```
GET /api/metrics/series?metric=<id>&window=1h|6h|24h|7d|30d&by=user|service|process|none
```

- `metric` 是**白名单 id**，例如 `gpu.vram_used`、`host.cpu_util`、`user.mem_rss`、`engine.slots_busy`、`gateway.requests`、`gateway.latency`。BFF 的身份守卫禁止 `query` / `promql` 这类自由查询参数，这里同样不接受任何表达式。
- 返回值：

  ```json
  {"metric": "gpu.vram_used", "unit": "mib", "window": "24h", "step_s": 300,
   "capacity": 49140, "thresholds": {"warn": 0.8, "critical": 0.95},
   "buckets": ["2026-10-23T00:00:00Z", ...],
   "series": [{"key": "account:fjd", "label": "fjd", "kind": "user", "me": true,
               "points": [{"avg": 41000, "max": 41900, "min": 40800}, null, ...]}],
   "events": [{"ts": "...", "kind": "service_start", "label": "strata 启动"}],
   "quality": {"coverage": 0.98, "source": "history-sqlite"}}
  ```

- 时间桶由服务端按窗口对齐，**每个系列最多约 300 点**。降采样方式：保留 max 与 avg，前端默认画 avg，tooltip 里给出 max。
- `events` 来自注册表与网关：服务启动 / 停止、GPU 借用、参数变更。前端画成竖向标注。
- 另提供 `GET /api/metrics/heatmap?metric=…&window=7d|30d&by=hour_of_week|day` 和 `GET /api/metrics/histogram?metric=gateway.latency&window=…&model=…`。

**可见性**：

- 按用户的明细默认对全实验室可见，当前用户标 `me: true`，这是之前定下的「人少，透明」。
- 增加实验室设置 `per_user_detail_visible`，由管理员控制。关掉之后，成员只能看到「我」和「其他人合计」。

## 5. 组件库（`web/console/js/viz/`）

**原则**：零依赖，ESM，SVG。几何计算写成纯函数，可以在 Node 下测试——沿用 `charts.js` 的写法。所有文本用 `textContent`。

| 文件 | 组件 | 要点 |
| --- | --- | --- |
| `scale.js` | `linear`、`time`、`band`、`niceTicks`、`timeTicks`、`fmtCompact` | 刻度取整（0 / 10K / 20K）；时间刻度按窗口选择 HH:mm、周几、MM-dd |
| `tooltip.js` | 单例 tooltip | 数值在前、名称在后；系列用短线条做图例键；跟随指针并自动避开边缘；键盘聚焦时显示同样内容 |
| `timeseries.js` | `timeSeries(el, spec)` | 折线 / 面积 / 堆叠面积；`capacity`、`thresholds`、`events`、`emphasis: key`、`band: [p5, p95]`；十字准线吸附最近时间桶；断线；`syncGroup` 让多张小图的准线联动；点击拖拽选区以放大，双击还原 |
| `sparkline.js` | `sparkline(values, {accent})` | 60×20，最后一点高亮；用于 KPI 卡片和表格列 |
| `stat.js` | `statTile({label, value, unit, delta, trend})` | 变化量带正负号与比较时段；颜色 = 方向 × 涨是不是好事 |
| `meter.js` | `meter(ratio)`、`bullet({value, target, previous, max})` | 填充颜色随严重程度变化；轨道用同色相的浅一级 |
| `bars.js` | 竖向 / 横向 / 堆叠 / 分组柱 | 柱宽 ≤ 24px；段与段之间留 2px 底色缝；标签放不下就移到柱外或只放进 tooltip |
| `heatmap.js` | 星期 × 小时、用户 × 小时、日历 | 顺序色 + 色阶图例；单元格本身就是命中区 |
| `swimlane.js` | 泳道时间线 | 每条泳道的占用段带开始 / 结束时间；正在进行的段画到「现在」，末端用渐隐表示 |
| `treemap.js` | squarify 算法，两层 | 小块不放文字；点击某块下钻 |
| `sankey.js` | 3–4 列冲积图 | 节点高度 = 流量；连线用源节点颜色的 25% 不透明度；悬停高亮一条路径 |
| `distribution.js` | 直方图、箱线图、分位带 | 直方图分箱用 Freedman–Diaconis 规则，上限 40 箱 |
| `scatter.js` | 散点 | 点半径 ≥ 4，外圈 2px 底色环；用网格索引找最近点，命中半径 24px；≤ 3 色 |
| `legend.js` | 共享图例 | 两个及以上系列必须有图例；点击图例 = 切换强调，不是隐藏系列 |
| `frame.js` | 卡片外框 | 标题、副标题、「图 / 表」切换、「在 Grafana 中打开」、空态 / 未知态、重新取数时保留旧帧并降低不透明度 |
| `filters.js` | 全页筛选条 | 时间范围预设（1 小时 / 6 小时 / 24 小时 / 7 天 / 30 天）、维度（按用户 / 按服务 / 按进程）、「突出我」开关；状态写进 URL hash（`#/usage?w=24h&by=user&me=1`） |

现有的 `sunburstPanel`、`vramPanel`（点阵）、`donutPanel`、`heatmap`、`windowBars` 迁入 `viz/`，改用新 token。环形图只保留在「≤ 6 段、且差异明显」的场景。

**动效**：首次进入时，线条从左往右描出（400ms），柱子从基线升起（300ms，缓动 `--ease`）。`prefers-reduced-motion` 时关闭全部动效。更新数据时直接过渡，不重播入场动画。

## 6. 各页面设计

页面顶部统一是：筛选条 → KPI 卡片行 → 图表网格。图表网格用 12 列，卡片占 12 / 8 / 6 / 4 列；宽度小于 720px 时一律满宽。

### 6.1 资源监控 `#/usage`（重点）

筛选条：时间范围、维度（按用户 / 按服务）、突出我。

| 区块 | 图 | 回答的问题 |
| --- | --- | --- |
| KPI 行（8 张，每张带 sparkline 和变化量） | GPU 显存、GPU 利用率、功耗、温度、CPU、内存、Swap、磁盘 IO | 现在怎么样，比 1 小时前如何 |
| **GPU 显存水位**（12 列） | 按用户 / 服务堆叠的面积图 + 48 GB 容量线 + 80% / 95% 警戒带 + 服务启停事件标注 | 谁在什么时候占了多少，离满还有多远 |
| GPU 状态小图组（12 列，三张小图共享时间轴） | 利用率、功耗、温度 | 卡忙不忙、热不热（不用双纵轴） |
| **GPU 占用泳道**（12 列） | 每个用户 / 服务一条泳道 | 谁、在什么时段占着卡，空闲多久了 |
| 内存水位（8 列） | 按用户堆叠的面积图 + 物理内存容量线 | 内存是谁用掉的 |
| Swap（4 列） | 面积图 + 容量线 | Swap 已满时直接显示红色状态 |
| CPU（8 列） | 按用户堆叠的面积图，单位为核，以总核数为顶 | |
| 使用规律（4 列） | 用户 × 小时热力图，指标可选 CPU / 显存 / 内存 | 谁通常在什么时候用 |
| 磁盘（6 列） | 每个挂载点一条子弹图（当前已用、上周同时、总量）+ 已用量趋势线与线性外推，标出「预计 N 天后满」 | 盘还够不够 |
| 磁盘与网络 IO（6 列） | 两张共享时间轴的小图 | |
| 按 Linux 用户表（12 列） | 表格，每行带 sparkline；「我」行高亮 | 精确数值 |
| GPU 进程表（12 列） | pid、用户、服务、显存（带 sparkline） | |

## 7. Grafana 的位置

- 控制台负责**日常用的、按业务组织的视图**：按人、按服务、按密钥，配合我们的权限模型。
- Grafana 负责**深挖**：任意时间范围、任意 PromQL、告警。
- 每张图的卡片框提供「在 Grafana 中打开」，链接带上同样的时间范围（`from` / `to`），只对管理员显示（Grafana 本身不认我们的账户）。
- `deploy/grafana/dashboards/` 里补一套与控制台对应的面板（GPU 水位、按用户资源、引擎负载），数据源是 Prometheus 抓取的 `/metrics`（§4.2）。上线需运维批准。

## 8. 交互规范

- **十字准线**：竖向发丝线吸附最近的时间桶。tooltip 列出该时刻所有系列的值，按值从大到小排；「我」置顶并加粗。
- **联动**：同一页面中 `syncGroup` 相同的时间序列图，准线位置和放大选区都同步。
- **放大**：在时间序列图上横向拖拽选区放大，全页的图跟着变；顶部出现「重置时间范围」。
- **图例**：点击 = 强调该系列（其他变灰）；再点一次取消。不提供隐藏系列的功能，避免误读堆叠总量。
- **事件标注**：竖线 + 顶部小圆点，悬停显示事件内容，点击跳到相关页面（如服务详情）。
- **键盘**：图卡片可以聚焦；← / → 在时间桶之间移动准线；Enter 打开表格视图。
- **空态**：数据源未接入时显示平静的说明；有数据源但这段时间没有数据时，画出坐标轴并标注「这段时间没有记录」；读取失败如实说明。

## 9. 性能

- 每个系列最多 300 点（服务端降采样），每张图最多 8 个系列加「其他」。SVG 足够，不需要 Canvas。
- 页面级缓存：同一个 `metric + window + by` 在 30 秒内复用。
- 自动刷新：24 小时窗口每 60 秒刷新一次，1 小时窗口每 15 秒；页面隐藏（`visibilitychange`）时暂停。
- 采样器的 CPU 占用应小于 1%（单核），实现者需要实测并写进 PR。

## 10. 测试与验收

- **纯函数单测**（Node）：刻度、降采样、堆叠、squarify、桑基布局、直方图分箱、颜色映射（同一 id 稳定、溢出后合并为「其他」），以及断线（`null` 不进路径）。
- **后端**：采样器在缺测时写 `NULL`；汇总的 min / avg / max 正确；过期清理正常；接口拒绝非白名单的 `metric`；关掉 `per_user_detail_visible` 后成员只拿到「我」和「其他」。
- **浏览器**（现有 harness）：每个页面在浅色、深色、390px 下截图；没有横向溢出；表格视图可达；键盘能移动准线。
- **校验器**：把 §2.1 的两条命令加进 `tests/`（或 CI 脚本），色板改动必须重新通过。
- 演示数据：`demo.js` 为每个指标生成可信的 24 小时 / 7 天曲线（以快照数值为锚点、确定性随机），页面顶部保留「演示数据」提示。
