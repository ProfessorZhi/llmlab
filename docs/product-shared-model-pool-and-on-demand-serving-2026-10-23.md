# LLM Lab：多用户共享模型池与按需推理平台 — 产品需求及架构草案

> 状态：**DRAFT / 待产品评审**  
> 日期：2026-10-23  
> 范围：单台 Dell RTX A6000 多用户 Linux 实验室；保留未来扩展节点的可能性。  
> 性质：**产品需求、建议方案与待确认决策**。本文不表示实现完成、生产上线许可或网络暴露授权；不修改服务、磁盘及账户权限。

## 0. 一句话定位

**LLM Lab 是共享 GPU 实验室的统一模型与推理服务工作台：用户专注模型下载、微调和引擎实验；平台尽量自动发现和登记资源，协调 HDD/SSD 存储、模型版本、共享权限和运行实例，提供 GUI、CLI、独立 API Key、统一推理入口、监控及评测。**

核心价值不是重做 vLLM / SGLang / Strata、Prometheus / Grafana 或 EvalScope 的功能，而是连接现有工具，打通「**资源发现 → 登记与共享 → 申请运行 → API 调用 → 观测/评测 → 归档**」的流程。

## 1. 需求的确定程度

- **用户明确诉求（需求方向）**：多名 Linux 用户在同一 GPU 机器上微调模型、修改推理引擎；希望 GUI 和 CLI 都能查看和操作，自动发现/注册尽量减少人工维护；共享稳定模型与引擎环境；模型可按需启动，提供每个调用方**独立** API Key；期望获授权的外部 API 客户端**不必加入 Tailscale**；兼顾 SSD、机械盘、用户私人空间及共享空间。
- **本文件提出的实现建议（尚待评审）**：私人实验区 + 共享不可变发布库 + SSD 热缓存；用户权限下扫描私人目录、平台权限下扫描共享目录；轻量运行控制器和受限启动器；推理 API 与管理 API 分开暴露；对 checkpoint 自动发现、验证及版本关联。
- **仍需明确批准**：生产互联网入口、宿主执行权限、创建/变更目录 ACL、共享引擎环境安装、实际 GPU 启停与迁移、缓存清理/备份及正式部署。本文不构成这些操作的批准。
- **旧文档存在冲突**：`architecture-v1-simplified.md` 的旧 D1「用户自己启动、平台不启停」与新需求的**平台可按需启动**不一致；`v1/TARGET_ARCHITECTURE.md` 中 Linux/PAM 作为平台登录权威的历史描述，已被独立平台账号决策取代。实施前需要正式 ADR 更新，不能默默沿用旧假设。

## 2. 用户角色和需求场景

| 用户 | 希望完成的事 | 平台应承担 |
| --- | --- | --- |
| 模型/微调开发者 | 复用基础模型、私有微调、保存若干 checkpoint、选稳定版本发布 | 模型发现、版本关联、位置索引、共享与存储策略 |
| 引擎开发者 | 安装或修改 vLLM/SGLang/Strata 等引擎，验证定制版本 | 版本化运行环境、兼容性验证、实验环境与受信环境隔离 |
| 普通实验室成员 | 发现已共享模型、按需启动或复用、在线调用/测评 | 稳定 Endpoint、调用权限、资源排队与状态、个人用量 |
| CLI / 编程 Agent | 脚本化发现、下载、注册、启动、部署、测试 | 与 GUI 一致的 API、机器可读回执、最小权限 Token |
| 平台运维者 | 控制共享盘、GPU 容量、授权、日志、备份 | 可审查的变更、真实指标、失败回滚；不需逐个替用户操作 |

### 2.1 核心业务闭环

1. 用户通过 Web、CLI、Claude Code 或已有训练工具下载/生产模型和 checkpoint。
2. 平台的**授权**发现器识别资源；完整的私人产物自动进入该用户的私有资源索引，不自动对全体开放。
3. 用户可选择将稳定模型、LoRA Adapter 或经过审核的引擎环境**发布到共享池**；公共版本不可原地覆盖。
4. 使用者选择已授权模型、引擎和部署配置，CLI 或 Web 发起「启动/复用服务」任务。
5. 控制器检查真实 GPU/RAM/磁盘可用性、权限及已有实例；必要时准备 SSD 热副本，并通过受限执行器启动；**只有实际就绪且 Gateway 路由确认后**才标记可调用。
6. 各调用者用自己的 Key 调用统一 Endpoint；请求、权限和元数据按调用者隔离。
7. Prometheus/Grafana 提供底层指标，EvalScope 提供评测执行；LLM Lab 把这些结果关联回模型版本、部署与用户。

| FR-11 | P1 | **Checkpoint 版本树**：自动关联 base model、训练 run、step、格式（完整权重/LoRA/恢复快照）、完成状态与可部署性。 |

| FR-13 | P1 / 门禁 | **无需 Tailscale 的外部 API 消费**：获批准的客户端可经独立 HTTPS 推理入口调用；管理面、监控面和宿主端口不因此公开。公开入口需单独审批。 |

> P0/P1 是本提案的新路线内部排序，**不覆盖**现有生产发布安全门禁。

## 4. 领域模型：必须区分的资源对象

| 对象 | 定义 | 关键原则 |
| --- | --- | --- |
| Model | 面向用户的逻辑模型与任务能力 | 不等于一个目录或端口 |
| Artifact / Checkpoint | 一个明确的模型权重或 Adapter 版本 | 同名不同训练 run 不得混淆 |
| Artifact Location | 某版本在某磁盘/授权目录的物理位置 | 一个版本可同时有 HDD 正本和 SSD 缓存 |
| Engine Runtime | 安装好的引擎及版本/环境（如 vLLM 某版本） | 不等于正在运行的进程 |
| Engine Instance | 受信记录的一次真实进程/服务实例 | 状态、归属、管理能力单独验证 |
| Deployment | Artifact + Runtime + 参数 + 资源申请 | 相同可复用配置可共享实例 |
| Endpoint | 对外稳定别名及经确认的路由 | 内部位置、端口变化不应变更外部接口 |
| Experiment Run | 微调任务、训练配置、基础模型、checkpoint 树 | 用于跟踪血缘，不等于生产服务 |
| Storage Lease | 正在运行/备份/校验任务的文件引用 | Lease 存在时禁止缓存回收 |
| Principal / Grant | 平台主体、资源归属与操作权限 | 平台身份独立于 Linux UID；宿主操作需另行授权 |

现有 Registry 的 Engine/Model/Deployment/Endpoint 能复用，但新增 Artifact/Location、Runtime、Experiment Run、Storage Lease 时应**扩展模型并迁移数据**，不要另造一套彼此不同步的登记数据库。

## 5. 推荐磁盘结构与责任边界

### 5.1 物理前提

目标是当前约 **500 GB 级 NVMe SSD（系统根目录）+ 2 TB 级机械盘（`/data`）+ RTX A6000 48GB** 的 Dell。无需给每个用户重新分区；目录归属、ACL 和按需文件系统配额更适合。

> `docs/benchmarks/2026-10-23_iq2xs_nvme_vs_hdd/summary.md` 的特定 Strata/IQ2_XS 实测：NVMe 冷启动约 68 秒、HDD 约 378 秒；1,024 token 解码约 127.1 对 17.6 tok/s。这证明该 workload 的实时服务应优先 NVMe，**不能推断所有模型的 HDD 性能都相同**。

### 5.2 建议目录（待授权创建，非既有目录承诺）

| 区域 | 建议路径 | 管理者和规则 |
| --- | --- | --- |
| SSD 私人 HOME | `/home/<user>/` | 代码、配置、凭据、小型开发环境；**避免囤积大权重** |
| SSD 公共引擎 | `/opt/llm-engines/<engine>/<version>/` | 平台/运维安装的不可变、可共享固定版本；个人实验不能写入 |
| SSD 热模型副本 | `/srv/llm-lab/model-cache/` | 平台可管理、可回收副本；不得充当唯一原件 |
| SSD 平台状态 | `/srv/llm-lab/` | 受保护的服务状态、SQLite 等，按一致性备份策略处理 |
| HDD 用户私人模型 | `/data/home/<user>/models/` | 用户原件，默认私有；平台仅在授权后发现与索引 |
| HDD 用户 checkpoint | `/data/home/<user>/checkpoints/` | 用户训练恢复点和私人稳定产物 |
| HDD 项目实验区 | `/data/projects/<project>/` | 经项目 ACL 授权成员写入；允许共享基础模型进行微调 |
| HDD 公共发布库 | `/data/shared/models/` | 正式发布的不可变模型版本；只有平台发布者可写 |
| HDD 数据集 | `/data/shared/datasets/` | 可共享的数据集或受限数据集，按单独 ACL |
| HDD 临时区 | `/data/scratch/` | 有界、可回收的暂存/测试产物，**不是可信模型发布源** |

现有 Strata 安装和模型数据先按受信已有服务接入，**不迁移、不覆盖，不因规范化而中断**。公共模型库不是全员可直接覆盖的世界可写目录。

**模型默认放哪里：**

- 普通用户自行下载与微调产生的**原件**：优先自己的 HDD 目录；需要高频写入时申请有上限的 SSD 实验空间。
- 用户通过平台显式创建的「实验室公共模型」：下载完成、校验并授权后，直接作为共享 HDD 不可变版本。
- 共享基础权重优先多用户**引用一份受控副本**，而不是人人下载完整副本；LoRA/Adapter 可只保留小型增量权重。
- 交互式部署需确认性能时，选择性从 HDD 准备**SSD 热副本**；运行结束仅回收热缓存，不删 HDD 正本。
- 是否允许他人通过 API 调用、下载权重、创建部署、修改环境、停止实例，是五种不同权限。

**容量策略（待测定）**：SSD 系统空闲空间设保护阈值；模型热缓存有硬预算、容量预留、并发复制限制与 Lease；私人用户及共享库分别统计物理/逻辑使用量。不要把当前剩余 SSD 全承诺给缓存。HDD 当前是否具备底层冗余尚未证明；不可再生的 checkpoint、数据库与实验产物必须另有备份。未实施 XFS quota 时，业务配额不能阻止用户直接 SSH 写满磁盘。

## 6. 自动发现与自动注册：轻量、边界明确

### 6.1 三种来源

1. **公共目录扫描器**：平台在已授权的公共模型库、公共引擎安装目录与项目公开区域做只读、有界扫描。
2. **用户侧扫描器**：由对应 Linux 用户身份、按用户授权目录运行的短时 Python 任务；CLI 同步或可选 `systemd --user` 定时器；向平台上报经过裁剪的元数据。**平台账户不会获得该用户的 Linux 文件访问权**。
3. **显式事件和登记**：平台下载器、微调/训练任务完成回执、CLI/Agent 注册、已管理的 Engine Instance 心跳；优先用明确回执减少扫盘。

已有 `backend/registry/local_discovery.py` 支持 GGUF/HF 候选、有限深度与条目、获准端口只读探测；已有 `llmlab discover`、`models register`、`engines register`。目前主要是**候选发现与元数据登记**，不等于 checkpoint 版本系统、公共发布与自动运行全部完成。

### 6.2 成本约束

- Python 标准库 + SQLite；不引入模型推理、PyTorch 或常驻 Claude Code。
- 扫描只读配置、小型 manifest、文件名、大小、mtime；**不反复读取几十 GB 权重或对每个文件全文哈希**。
- 限制每次根目录、深度、条目、耗时、并发、配置文件大小；CPU/I/O 低优先级。
- 公共目录定时对账及 GUI 点刷新；用户侧短时扫描任务仅在获得授权时运行，无法调用时明确显示「扫描器不可用/上次同步时间」，不能假装刷新成功。
- 可选 inotify 监听变更；不能依赖通知保证所有嵌套目录事件不丢失，仍需周期性对账。

### 6.3 发现、登记、共享、运行是四个不同状态

`DISCOVERED` 候选 → `VERIFIED_PRIVATE` 私人已验证 → `PUBLISHED` 共享已发布 → `DEPLOYED_READY` 运行且路由就绪。

- 私人目录中发现新资源，最多自动登记到**所属者私人索引**，验证不充分时停留待验证候选。
- **扫描到某端口/进程、同名文件、用户自报路径，不是所有权证明。**
- 公共发布需要资源所有者授权、版本冻结、数据完整性检查及适当审查。
- 新服务需受信运行记录及实际健康/模型/路由回执才可以调用；注册成功不等于 GPU 已加载。

## 7. 微调与 checkpoint 版本体系

允许用户在自己区域或经授权的 `/data/projects/<project>/` 中自由实验，不可直接修改公共不可变模型版本。

一个实验的完整关系：

`Base Model@revision → Experiment Run ID → Checkpoint(step, type, artifact fingerprint) → Verified Candidate → Published Version（可选）`

识别规则：

- 优先使用平台训练任务的完成回执、实验/run ID、基础模型版本、训练配置、文件清单与保存完成标记。
- 对 Trainer/PEFT 等已知格式，辅助识别 `checkpoint-<step>`、`adapter_config.json`、`adapter_model.safetensors`、`trainer_state.json` 等；具体格式需插件化适配。
- 运行中写入文件、目录短期仍变化、缺必要分片或完成证据时标记 `INCOMPLETE/UNKNOWN`，**不自动部署或公开**。
- 仅相同步数并不能证明是同一 checkpoint；不同 run、模型 base、LoRA/全量产物应分开管理。
- 完成并验证后的 checkpoint 可以自动进入该用户的私人版本历史；**稳定发布、共享下载权限和公开 Endpoint 需显式选择**。
- 对未知 `.pt` / pickle 等任意文件，不要在扫描器里反序列化或加载执行；由后续受限插件验证。
- 推理权重、训练恢复快照、LoRA Adapter 要单独标类型和可部署状态；EvalScope 结果可辅助选择版本，但不会替用户自动把最高 step 标成最佳。

## 8. 推理引擎的共享与运行

### 8.1 「共享环境」不等于「共享进程」

- **共享稳定引擎环境**：`/opt/llm-engines/<engine>/<version>` 固定安装物，可由多个有权限的部署使用。
- **私人实验环境**：用户可 fork 或修改 vLLM/SGLang/Strata；不允许直接修改公共版本；测试通过后申请发布新的不可变 runtime 版本。
- **服务实例**：每次启动是单独的 Deployment/Instance；兼容的多个调用者可以复用同一个实例，但模型权重、运行参数和隔离策略不同则不能机械复用。
- **attach existing**：登记用户/运维已启动的受信服务，默认不获得启动/停止权。
- **managed serving**：由平台控制器提出启动计划、资源准入，交给获授权的受限宿主执行器启动、检查并回报；**不是开放任意 Shell/SSH/root**。

### 8.2 按需启动的目标流程

`llmlab services start（拟议）` 或 GUI「启动并使用」
→ 验证主体可调用/可启动
→ 查找可复用实例
→ 选择模型 Location 与允许的 Runtime
→ HDD→SSD 热副本准备（需要时）
→ GPU/CPU/RAM/端口容量准入与去重排队
→ 授权的宿主执行器启动
→ 验证真实模型、就绪与 Gateway 版本路由 ACK
→ 返回稳定 Endpoint 与任务状态。

- 推理模型未就绪时提供异步任务/排队状态，不让普通 OpenAI 兼容调用无限等待冷启动。
- 不因新模型请求自动终止他人任务；空闲回收只作用于授权托管实例并考虑活跃请求、评测和文件 Lease。
- 单 A6000 的显存不能保证多个大型模型同时运行，须有明确「资源不足/排队」状态。
- CLI 的新 `start / stop / runtime install / checkpoint publish` 等是**建议扩展命令，不是已有实现**；Web/CLI 走同一授权 API。

## 9. API 独立、模型服务可共享；外部无需 Tailscale 的目标

### 9.1 统一调用面

- 每个用户或外部应用拥有自己签发、可过期和撤销的 Key，授权到可调用的模型集合；**不共享 Key 明文**。
- 多个 Key 可以调用同一个获准共享的部署实例；Gateway 负责鉴权、解析可调用模型、转发流式响应、记录 request_id / 延迟 / 可得 Token 统计与主体归属。
- 不默认保存 prompt/completion 正文；跨用户请求元数据、报告和权限严格隔离。
- 权重下载权限与 API 调用权限分开；调用已就绪服务也不应自动获得「启动 GPU 任务」能力。

### 9.2 「不用 Tailscale」的边界

用户的目标是：**调用模型的外部客户端不必加入实验室的 Tailnet**。这不是目前的网络事实，也不等于管理后台必须公开。

建议的目标拓扑：

`外部获授权客户端 → 独立的 HTTPS 推理入口（唯一获准的 /v1/* 等）→ Gateway → 内部引擎`

同时：

`实验室成员 → 受保护的管理入口（仍可保持 Tailnet-only）→ GUI / 管理 CLI API`

公网/跨网调用需要运维**单独批准** DNS/证书、入口、防火墙/反向代理、访问与滥用限制、Key 安全、连接数/请求体上限、资源保护、审计与撤权验证；不能把现有管理路由、Prometheus/Grafana、Strata 原始端口一并暴露，更不能未经批准改动 Caddy/Tailscale、443/8443 等现有入口。公网入口的基本容量/滥用保护与是否实行用户账单/配额是两件事。

> 另一个可接受方案是保持全部服务仅 Tailnet 内访问。**外部无 Tailnet 的需求应作为独立设计决策与上线门禁，不承诺文档合并后立即可用。**

## 10. GUI、CLI 与工具复用

### GUI（保留现有 V6.2 Apple 风格）

以用户任务为信息架构：`总览 / 模型池 / 引擎环境与部署 / Playground·API / 我的调用 / 监控 / 评测 / 设置与审计`。

每个资源详情页展示：类型、版本、所有者、可见性、磁盘位置等级（不泄露私人绝对路径）、实际空间、运行能力、关联 checkpoint、就绪状态、可执行动作及审计回执。支持「刷新我的资源」「发布稳定版本」「启动并使用」「运行评测」。

### CLI / Agent

复用已有 `llmlab discover`、`models/engines/deployments/endpoints`、`invoke` 及 JSON 输出。建议按现有 API 风格扩展如下能力（**命令名待设计，并非当前可执行命令**）：

- `llmlab sync`：以当前用户身份扫描并上报授权私人资源。
- `llmlab models publish` / `checkpoints list`：发布冻结版本、查看实验历史。
- `llmlab runtimes list/install/inspect`：查询/申请已批准的运行环境。
- `llmlab services start/status/stop`：异步按需部署及状态查询。
- `llmlab eval submit/status`：评测任务和回执。

Claude Code 的 `CLAUDE.md` 可以只指导遵循统一存储规范与 CLI，不是资源权威，也不应通过常驻 Claude Code 扫全体用户私人目录。

### 不重复造轮子

- Strata/vLLM/SGLang 等：模型推理与可选原生能力，由引擎适配器映射。
- Gateway：服务 API、Key 鉴权与调用日志；保持薄层，不承担磁盘扫描和 GPU 编排。
- Prometheus：采集可信主机/GPU/引擎/Gateway 指标。
- Grafana：高级监控 UI；LLM Lab 展示常用业务视图，可提供受控跳转。
- EvalScope：评测与压测执行及原始报告；LLM Lab 负责权限、任务准入、版本关联与结果入口。

## 11. 安全与故障准则

- **独立平台账户**：平台登录用自己的账户/密码验证器；Linux UID 只在受授权的宿主文件、进程操作中作为独立适配的执行主体。
- **禁止跨用户扫描**：平台服务不能因为用户网页登录就读取别人的 HOME；用户侧扫描器以对应 Linux 用户的有效权限运行。
- **不可变公共资源**：未经授权不得写公共引擎版本和公共模型；不能把 world-writable 暂存路径当可信发布目录。
- **私有数据保护**：private 模型/路径/报告、API Key、训练数据和调用明文不可因模型共享而自动公开。
- **不能伪造可用性**：DISCOVERED、REGISTERED、VERIFIED、RUNNING、ROUTED、READY 分开；UNKNOWN ≠ 0。
- **可恢复**：平台注册、SSD 晋升、下载与发布必须幂等，支持失败回滚；任务失败保留私人原件，断线不能假装完成。
- **安全删除**：仅回收有经验证冷副本、无活跃 Lease 的平台热缓存；不能自动删除私人源文件、不可再生 checkpoint 或其他用户服务。
- **可复现**：部署/评测绑定 artifact revision、runtime version、配置快照及来源证据。
- **生产变更单独授权**：部署、入口暴露、宿主目录 ACL、清理、迁移、服务启停不是文档 PR 的附带权限。

## 12. 迭代路径与验收定义

| 里程碑 | 建议先交付什么 | 可证伪的验收 |
| --- | --- | --- |
| M0：契约与基线 | 审核现有目录、权限、运行环境，定资源模型/安全策略，保留当前服务和代码 | 确认不覆盖现有用户目录/Strata；新旧文档冲突有 ADR |
| M1：资源发现 | 扩展现有发现器；公共有界扫描 + 用户侧有限任务 + GUI 刷新/CLI 同步 | 用户新建模型、完成 checkpoint 后，私有索引出现；他人不可见；扫描不读取大权重 |
| M2：公共资源池 | 冻结 Artifact 版本、模型发布、引擎 runtime manifest、共享授权 | 公共模型可被多个用户复用；不可覆盖旧版本；取消授权及时阻断 |
| M3：受限启动 | attach/managed 双模式、GPU 准入、SSD 热缓存、Deployment/Router 就绪检查 | 并发相同请求只启动一次；资源不足排队；他人现有服务不受影响 |
| M4：服务和评测闭环 | 个人 Key、统一 Gateway、Playground、EvalScope、Prometheus/Grafana | 真实模型经 Gateway 可调用；个人调用归属正确；版本/评测数据可追溯 |
| M5：外部调用 | 独立审批的 HTTPS 推理入口及防滥用措施 | 无 Tailnet 的获准客户端能调 `/v1/*`；不经授权不能访问管理面/内部端口 |

最小核心验收场景：

1. A 在私人实验区保存 checkpoint，扫描器只把已完成且被验证的版本登记到 A 的私人索引，B 看不到。
2. A 明确发布某版本，B 能使用该已授权共享模型；B 没有其权重下载权限时仍不能拿到文件。
3. 两位使用者通过各自 Key 调用同一个可复用实例，Gateway 可独立归属日志，撤销 Key 后下一次调用拒绝。
4. 用户发起按需启动时，模型需在 HDD→NVMe 晋升、资源准入与服务就绪后才能进入 READY；SSD 回收不影响 HDD 正本。
5. 模型换目录、换端口不改变稳定模型/Endpoint 身份；来源不可信或匹配不唯一时停止自动改指向。
6. 外网 API 仅在专门授权的入口上线后测试；管理入口、SSH、原始推理引擎不暴露。
7. 不通过更改现有 GPU 作业、用户 HOME 权限或扩大 Fleet/CloudCLI 许可获取「绿灯」。

## 13. 仍需产品负责人决策的问题

1. **外部访问范围**：仅个人设备/已批准合作方，还是面向开放互联网？是否接受独立的推理 API 公网 HTTPS 入口？
2. **共享默认策略**：私人实验默认 private 已明确；平台代下载的开源基础模型是默认共享（需明确下载许可）还是逐次确认？
3. **启动权与资源公平**：任何被授权调用者是否可申请冷启动？同时请求的排队优先级和保护阈值是什么？
4. **团队项目**：是否第一期需要 `/data/projects/<project>` 可写协作区，还是先完成个人 + 公共池？
5. **存储预算**：SSD 热缓存最大值、个人/共享 HDD 预算和不可再生 checkpoint 的备份责任。
6. **实验产物晋升**：checkpoint 自动私人登记后，默认仍需人确认是否发布为共享/可调用版本（建议如此）。
7. **引擎公共版本准入**：哪些软件/安装环境属于管理员审核的可信可共享 Runtime？

## 14. 与当前仓库的关系

- **延续既有**：独立平台认证、Apple 管理界面、Registry + ACL + CLI、`local_discovery.py` 受限扫描、Gateway、Observability、EvalScope 适配、CI/安全审查。
- **需要新增/明确**：Artifact/Location/Experiment Run/Engine Runtime 数据结构；轻量 per-user sync；受控公共发布；Storage Manager；受限运行控制器；API 外网暴露方案及批准流程。
- **避免方向偏差**：不把整台机器做成 K8s 集群，不重造推理框架或完整 Grafana，不用 Claude Code 常驻维护所有用户磁盘，不因能读端口就认为能控制他人服务。
- **变更纪律**：本需求文档只供设计审查；不得因其进入 GitHub 而实施 SSD/HDD 搬迁、重设权限、修改 Strata/Gateway/Caddy 或开放生产网络。
