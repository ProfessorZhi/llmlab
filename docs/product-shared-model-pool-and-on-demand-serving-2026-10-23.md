> 状态：**历史设计，非当前产品定义**（2026-10-27 裁决）。当前产品是个人资源管理，
> 跨用户共享暂缓；本文中与 [产品定义](product-definition-2026-10-27.md) §2 冲突的
> 部分（服务共享、自动发布、管理员代操作）不实现，保留作后续版本的讨论基础。  
> 原文状态：DRAFT / 待产品评审（2026-10-23 修订：按讨论结论收窄范围）  
> 范围：单台 Dell RTX A6000（48 GB）多用户 Linux 实验室。  
> 性质：产品需求与已定决策。不构成生产部署、网络暴露或宿主权限变更的批准。  
> 实现规格：[资源自动接入、启动与服务共享 — 实现规格](design-lab-resource-agent-and-service-sharing-2026-10-23.md)

## 0. 一句话定位

**每个人在自己的工作区里自由下载、微调模型和改推理引擎；LLM Lab 自动发现这些资源、认得出它们被挪到了哪里，让用户（或替他干活的 Claude Code）一条命令就能把模型上线成服务，并把正在运行的服务按需共享给实验室——调用者用自己的 API Key，日志跟着 Key 走。**

平台不重做推理框架、监控或评测工具，只把「发现 → 上线 → 共享调用 → 观测」这条线打通，并协调唯一的那张 GPU。

## 1. 已定决策

| # | 问题 | 决定 | 理由 |
| --- | --- | --- | --- |
| P1 | 共享什么 | **只共享「正在运行的服务」的调用权**；模型文件、引擎 build **不共享**，各管各的 | 单卡 48 GB 只放得下一套大模型，共享调用是别人用上 GPU 的唯一办法；文件共享眼下没人需要（重复只有几百 MB），却要一整套发布 / 权限 / 不可变版本机制 |
| P2 | 谁起服务 | **用户的服务只以用户本人身份运行**：手动起，或在网页 / CLI 里点「启动」，由**本人的代理**起；平台和管理员都不以别人的身份起服务 | 平台读不到别人的私人目录；以别人身份执行等于越权。与 [简化架构 D1](architecture-v1-simplified.md) 一致 |
| P3 | 平台公共服务 | 管理员可以起**平台托管服务**（以平台服务账户运行，模型放在平台区）；普通用户不能起平台托管服务 | 实验室常驻服务（如 Strata）不应挂在某个人名下 |
| P4 | 共享开关 | 服务**默认私有**；主人可开「全实验室」；管理员可改任何服务，并设定实验室**默认策略**（新服务默认私有 / 默认开放） | 先保守，习惯后由管理员一键切换；不做「上线 N 天自动开放」这类定时行为 |
| P5 | API Key | **每个调用者自己建**，绑定调用者，不绑定服务；可限模型、限速、有效期、随时撤销；**从不共享** | 调用者不用去服务主人那里申请；主人看不到别人的 Key |
| P6 | 日志 | **以 Key 为单位**：调用者看自己每把 Key 的完整日志（正文仅在该 Key 打开记录时有）；服务主人只看「谁调了我、多少次、多少 Token」；管理员看全部 | 隐私跟着调用者，统计给主人 |
| P7 | 存储 | **SSD / 机械盘放什么由用户自己决定**；平台负责发现、按指纹识别移动、给空间报告和建议，**从不主动移动或删除用户文件** | 规范靠工具变顺手，而不是靠强制 |
| P8 | 公共区 | 只保留一个**平台区**：管理员写、成员只读，存平台托管服务用的模型与稳定引擎 | 不做用户发布流程、投递区、五级权限 |
| P9 | 主要操作入口 | **`llmlab` CLI**（JSON 输出、可预演、明确退出码），Claude Code 在用户终端里用它一键完成挪动、上线、共享；GUI 负责看与开关 | CLI 以用户身份运行，天然拥有正确的文件权限 |
| P10 | 停别人的服务 | 普通用户只能「申请借用 GPU」；管理员可在 GPU 冲突时停止任何服务（规则事先告知，留审计） | 单卡必须有人能仲裁，但要透明 |
| P11 | root | 只在**一次性安装**时使用（目录、ACL、全局用户级服务、linger）；平台日常运行不持有 root。**已确认：管理员一次性全局启用每用户代理**，用户无需任何操作 |
| P12 | 自动登记 | 用户下载的模型、编译的引擎由代理**自动发现并登记**到本人名下（默认私有）；运行中的服务由平台自动接入、自动开始监控与日志 |
| P13 | 参数 | 平台自动读取模型元数据（上下文上限、层数、KV 头数、量化）与引擎 build 实际支持的参数，**推荐启动参数并估算显存**；运行后以实测为准，主人可「应用并重启」 |
| P14 | 账密 | 本机身份走内核（`SO_PEERCRED`），不发密码；平台起的服务不设引擎密钥、只监听本机，鉴权全在网关；每人自动获得一把默认 API Key | sudo 组成员默认也读不到别人目录；常驻 root 风险过大 |

被本修订取代的旧提案：共享模型发布库与不可变版本、用户发布流程、reflink 投递区、五级权限、平台以任意身份按需启动、checkpoint 版本树（推迟，见 §6）。

## 2. 现状（2026-10-23 只读扫描）

- 用户：fjd、kaidong、laver（另有平台服务账户 llmlab）。
- 全机只有一个推理服务在跑：Strata（:8080，约 48 GB 显存），对外经 :8443 → :8081 → :8080；旧网关 :8200 无 UI。
- kaidong：4 个真实权重（约 64.5 GiB，含 59 GiB 的 gpt-oss-120b MXFP4，单卡放不下）、6 棵 llama.cpp 工作树（2 处可用构建），全部在 SSD 的 HOME 里；`/data/home/*` 建好后一直空着。
- 根盘（NVMe，约 500 GB）已用约 63%；`/data`（两块 1 TB HDD 的 LVM，XFS，约 2 TB）基本空闲。
- Strata IQ2_XS 基准：NVMe 冷启动 68 s、HDD 378 s；HDD 上 decode 只有 NVMe 的约 1/8（专家权重随机读）。**服务中的模型必须在 NVMe 上**，HDD 只适合放正本与归档。
- 原始扫描「116 套模型 / 49 个引擎」里只有 4 个模型、2 处构建是真的，其余是 llama.cpp 词表文件和源码；现有 `local_discovery.py`（深度 4、无大小下限）原样扫也会出同样的噪音。
- 目前没有人在机器上做微调；引擎开发（kaidong 的 probe）是真实需求。

## 3. 角色与能力

| 能力 | 普通用户 | 服务主人 | 管理员 |
| --- | --- | --- | --- |
| 自己的模型 / 引擎被自动发现、出现在「我的」 | ✓ | ✓ | ✓ |
| 起 / 停**自己的**服务 | ✓ | ✓ | ✓ |
| 共享开关 | — | 自己的服务 | 任何服务 |
| 实验室默认共享策略 | — | — | ✓ |
| 起 / 停**平台托管**服务 | — | — | ✓ |
| 停**别人的**服务 | 申请借用 | — | ✓（有审计） |
| 以别人身份起服务 | ✗ | ✗ | ✗ |
| 建自己的 API Key、看自己 Key 的日志 | ✓ | ✓ | ✓（可看全部） |
| 看「谁调用了我的服务」 | — | ✓（无正文） | ✓ |

## 4. 功能需求

| ID | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| FR-01 | P0 | **服务自动接入**：用户起的推理进程被自动发现，按进程 uid 归到对应平台账户名下，健康检查通过后出现在「我的服务」 | kaidong 手动起 llama-server，30 秒内出现在他名下；别人看不到（默认私有） |
| FR-02 | P0 | **按策略自动挂网关**：服务接入后按「主人设置 → 实验室默认策略」决定是否发布成网关模型名 | 默认私有时不出现在别人的模型列表；管理员切成默认开放后，新服务自动可被他人调用 |
| FR-03 | P0 | **模型 / 引擎自动发现**：在用户授权目录与 HF 缓存里发现模型（GGUF、HF、diffusers）和引擎 build（二进制 + git commit），默认只进主人的私人索引 | kaidong 的 HOME 只识别出 4 个模型、2 个 build；词表、源码、缓存不计入 |
| FR-04 | P0 | **移动识别**：按快速指纹识别移动与复制；移动后模型 ID、关联服务、评测记录不变；不唯一时停下等确认 | 把模型从 `~` 挪到 `/data/home/<user>`，平台只更新位置 |
| FR-05 | P0 | **共享调用与独立 Key**：多个调用者用各自 Key 调同一服务；撤销即失效；日志按 Key 归属 | 已实现（网关，PR #20）；本期补「按策略自动发布」 |
| FR-06 | P0 | **一键上线（网页与 CLI 同等）**：选模型 + 引擎 → 推荐参数与显存估算 → 由本人代理启动、等就绪、接入、按需共享；`llmlab serve` 等价；全部命令 `--json` | 下载一个 GGUF 后，不做任何登记，网页上点启动即可被实验室调用；agent 用 4–5 条命令完成同样的事 |
| FR-06b | P0 | **参数发现与调参**：读模型 facts 与 build 支持的参数；推荐参数带理由；运行后显示实测 vs 目标，主人「应用并重启」 | 推荐的上下文不超过模型上限、估算显存不超过可用显存；重启后实测值更新 |
| FR-07 | P0 | **GPU 看板**：谁占着 GPU、占了多少、空闲多久；对应哪个服务 / 进程 / 用户 | 与 `nvidia-smi` 进程表一致；未知就显示未知 |
| FR-08 | P1 | **空间报告与建议**：每人 SSD / HDD 用量；「大于 10 GB 且 7 天未用」的文件；重复副本 | 报告只读；建议需用户执行 |
| FR-09 | P1 | **`storage move`**：用户发起，先复制、校验指纹、再删源；可留软链接 | 中途失败源文件完好 |
| FR-10 | P1 | **GPU 借用**：申请 → 通知占用者 → 同意或超时后由占用者的代理停服务 → 借用结束提醒恢复 | 不会未经同意停掉别人的服务（管理员仲裁除外） |
| FR-11 | P1 | **平台托管服务**：管理员从平台区起停公共服务（如 Strata），运行参数用参数表 | 公共服务不依赖某个人的账户在线 |
| FR-12 | P1 | **多类型模型**：模型带 `task`（chat / vision / decision / embedding / rerank / image / video）与 `format`；网关按类型提供接口，视频等长任务走异步任务 | 先支持 chat、vision、decision；图像 / 视频按需排期 |
| FR-13 | P2 | **请求启动**：对别人未运行的模型发「请主人启动」通知，主人的代理以主人身份启动 | 只是一条通知，不改权限模型 |
| FR-14 | 门禁 | **无需 Tailscale 的外部调用**：独立 HTTPS 推理入口，只开放 `/v1/*` | 需单独安全设计与上线审批；管理面不随之暴露 |

## 5. 存储约定（用户自己管，平台给工具）

| 区域 | 路径 | 谁写 / 谁读 | 放什么 |
| --- | --- | --- | --- |
| 私人 SSD | `~/` | 本人 | 代码、配置、正在跑的模型（服务中的模型应在 NVMe） |
| 私人 HDD | `/data/home/<user>/` | 本人 | 模型正本、checkpoint、不常用的大文件 |
| 平台模型正本 | `/data/models/platform/` | 管理员写，成员只读 | 平台托管服务的模型 |
| 平台热副本 | `/srv/llm-lab/models/`（NVMe） | 平台 | 平台托管服务运行时加载 |
| 平台引擎 | `/opt/llm-engines/<engine>/<version>/` | 管理员写，所有人只读 | 稳定引擎；大家可直接用 |

- 建议（不是强制）：大权重的正本放 HDD，要上线时 `llmlab storage move --to ssd` 或 `serve --stage` 拷到 NVMe。
- 平台只读扫描用户授权目录；`~/.llmlab-ignore` 可排除目录。
- 平台从不删除用户文件；只回收平台区自己的热副本。

## 6. 推迟到有真实需求时

- **共享模型文件 / 发布库**：当重复副本超过约 50 GB，或有两人要基于同一基础模型微调时再做；指纹系统会给出数据。
- **checkpoint 版本树**：等机器上有人开始微调。
- **平台按需冷启动别人的模型**：P2 用「请求启动」替代。
- **硬性 GPU 管控**（限制 `/dev/nvidia*` 访问组）：会改变使用习惯，暂不做。

## 9. 与现有代码的关系

已有：独立平台账户、注册表与 ACL、`llmlab` CLI（`whoami` / `status` / `discover` / `engines` / `models` / `deployments` / `endpoints` / `usage` / `invoke`）、`local_discovery.py`、集成网关（每人 Key、模型路由、按 Key 日志、正文可选记录）、引擎参数表、资源监控与按用户占用。
